# Publication privacy

Public attribution intentionally uses only the supplied GitHub handles, Drefetr and magna-nz. The paper retains public scholarly citations and the collaborators' AI-workflow disclosure. No legal names, personal contact addresses or affiliations are inferred.

The publication audit checked tracked files and staged Git blobs, common credential/private-key patterns, personal path/email candidates, PDF metadata/XMP/text/links/objects/attachments and local Git metadata. One user-specific interpreter path was removed from an optional launcher. Scientific Python authorities, paper content and fitted results are unchanged. Portable operational variants and their source bindings are recorded separately from historical pins.

Before a later publication, inspect staged files, not just filenames or working-tree contents. Check the commit author/email that would be published. The prepublication audit began with no commits or personal commit-email metadata. The initial publication uses the repository collaborator's GitHub no-reply commit identity. Never add raw build logs, bytecode, local environment/configuration files, credentials or private investigation archives. Ignore rules are a safeguard, not a substitute for review, and do not protect a file already tracked by Git.

Project-relative provenance paths such as iteration/code/config names remain because they identify scientific authorities. Personal machine roots, home directories and hostnames are not needed for reproduction. Older local audit/build material has been moved outside the public tree and is not a release asset.

The findings and limits are in ../validation/privacy_audit.json. Pattern matching cannot guarantee detection of every possible sensitive value. Repository visibility and future commit metadata require separate attention when publishing. The recorded audit state is historical; inspect the live branch for later changes.
